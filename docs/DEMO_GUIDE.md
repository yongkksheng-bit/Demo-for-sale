# 面试演示指南 🎯

> 如何用这个项目在面试中惊艳全场

## 📋 演示前准备

### 环境准备
- [ ] 后端服务启动正常（`http://localhost:8000`）
- [ ] 前端页面打开正常
- [ ] 网络通畅（演示真实大模型需要联网）
- [ ] 浏览器全屏，页面放大到合适比例

### 心态准备
- 把面试官当成客户，你是销售顾问
- 自信、从容、有节奏
- 重点突出"我为什么做这个项目"和"我是怎么做的"

---

## 🎬 演示流程（建议 5-8 分钟）

### 第一步：开场介绍（1分钟）

**话术参考：**
> "面试官您好，我今天想给您演示一个我自己做的项目——火山引擎智能方案顾问。
>
> 为什么做这个项目呢？因为我之前在安得智联做大客户销售实习的时候，发现销售出方案效率很低，一个方案要写好几天，而且质量参差不齐。所以我就想，能不能用 AI 来提升销售的效率？
>
> 这个项目的核心功能是：输入行业和业务场景，30秒就能生成一份专业的解决方案建议书。"

**要点：**
- 先讲背景和动机，不是先讲技术
- 结合你的实习经历，真实可信
- 一句话说清核心价值

---

### 第二步：核心功能演示（3分钟）

#### 2.1 方案生成（重点演示）

**操作：**
1. 点击"立即开始生成方案"
2. 选择一个行业（建议选零售电商或金融，大家都熟悉）
3. 选择一个场景（建议选智能推荐或智能风控）
4. 点击"生成方案建议书"

**话术参考：**
> "我们来试一下，比如我是一个零售电商的客户，想做智能推荐和个性化营销。
>
> 选择零售电商行业，智能推荐场景，点击生成。
>
> 大家可以看到，现在 AI 正在分析行业痛点、匹配产品、设计方案架构、计算 ROI。
>
> （等生成完后）
>
> 好，方案生成好了。大家可以看到，这是一份完整的解决方案建议书，包含：
> - 行业背景与挑战分析
> - 整体解决方案架构
> - 火山引擎产品组合推荐
> - 分阶段实施路径
> - 客户价值与 ROI 估算
> - 为什么选择火山引擎
> - 下一步行动建议
>
> 整个过程不到一分钟，而传统方式，一个资深解决方案顾问写这样一份方案，至少要大半天。"

**要点：**
- 边等生成边介绍，不要冷场
- 生成完后快速浏览，重点讲结构和价值
- 对比传统方式，突出效率提升

#### 2.2 智能对话（快速演示）

**操作：**
1. 点击顶部"智能对话"
2. 输入一个问题，比如"豆包大模型有什么优势？"

**话术参考：**
> "除了生成方案，我们还有智能对话顾问，可以解答客户的各种问题。
>
> 比如客户问豆包大模型有什么优势，AI 会给出专业的回答。
>
> 这个功能相当于给每个销售配了一个 7×24 小时的资深技术顾问。"

**要点：**
- 快速演示，不要花太多时间
- 重点讲应用场景

#### 2.3 销售工具箱（快速演示）

**操作：**
1. 点击顶部"销售工具箱"
2. 演示销售话术生成或异议处理

**话术参考：**
> "我们还有销售工具箱，帮助销售提升成单率。
>
> 比如销售话术生成，输入行业和场景，就能生成专业的拜访话术。
>
> 还有异议处理助手，客户说太贵了、已经用了阿里云，AI 都会告诉你怎么应对。
>
> 这些都是从真实销售场景中提炼出来的，非常实用。"

**要点：**
- 选一个演示即可，不要都演示
- 突出"实用"、"解决真实痛点"

---

### 第三步：技术架构讲解（2-3分钟）

**话术参考：**
> "接下来我简单讲一下技术架构。
>
> 整个项目分为前后端：
>
> **后端**用的是 FastAPI + LangChain 技术栈，核心是 RAG 检索增强生成架构。为什么用 RAG 呢？因为如果只用大模型，可能会有幻觉，而且知识不够新。加上 RAG 之后，可以基于火山引擎的官方文档来生成方案，更准确、更专业。
>
> **向量库**用的是 Chroma，轻量级，本地部署，适合快速原型。
>
> **大模型**用的是火山方舟的豆包大模型，也就是字节跳动自研的大模型。为什么选火山方舟？一方面是因为这个项目就是面向火山引擎销售的，用自家的大模型更贴切；另一方面，火山方舟的 API 兼容 OpenAI 接口，接入非常简单。
>
> **前端**用的是 Tailwind CSS + 原生 JS，没有用 React 或 Vue，因为这个项目功能不算特别复杂，原生 JS 更轻量、加载更快。
>
> 整个项目是我从 0 到 1 独立完成的，包括需求分析、架构设计、前后端开发、UI 设计。"

**要点：**
- 不要讲太多细节，重点讲架构思路和技术选型的原因
- 突出你是独立完成的，全栈能力
- 自然地提到火山引擎和火山方舟，显示你对字节的产品很了解

---

### 第四步：延伸讨论（准备好被问到）

面试官可能会问的问题，提前准备好：

#### Q1: 这个项目的难点是什么？
**参考回答：**
> "我觉得主要有两个难点：
>
> 第一个是**Prompt Engineering**。怎么让大模型生成的方案既专业又有说服力，结构清晰，重点突出，这个需要反复调试 Prompt。我前前后后改了很多版，现在的效果还不错，但还有优化空间。
>
> 第二个是**RAG 的效果**。怎么让检索到的内容更相关，怎么把检索到的知识很好地融入到生成的内容中，而不是简单地拼接。这个需要在分块策略、检索算法、Prompt 设计上都下功夫。
>
> 当然，还有一个难点是**产品思维**。这个项目不只是技术实现，更重要的是要站在销售的角度，思考他们真正需要什么，怎么用 AI 真正帮到他们。"

#### Q2: 如果给你更多时间，你会怎么优化？
**参考回答：**
> "如果有更多时间，我想从几个方面优化：
>
> 第一，**知识库的完善**。现在因为时间关系，知识库还比较少。如果能把火山引擎所有的产品文档、解决方案、案例都爬下来，构建一个完整的知识库，生成的方案会更准确、更丰富。
>
> 第二，**流式输出**。现在是等全部生成完才显示，用户要等几十秒。如果改成流式输出，边生成边显示，体验会好很多。
>
> 第三，**更多销售工具**。比如竞品对比工具、ROI 计算器、客户画像分析等等，真正做成一个销售的全流程 AI 助手。
>
> 第四，**多用户和团队协作**。现在是单用户版本，如果加上用户系统、团队共享、方案管理等功能，就更接近一个真实的产品了。"

#### Q3: 这个项目如果真的给火山引擎销售用，你觉得会有什么问题？
**参考回答：**
> "我觉得可能会有几个问题：
>
> 第一，**数据安全和隐私**。销售的方案里可能会涉及客户的敏感信息，怎么保证数据安全，这个很重要。
>
> 第二，**内容的准确性**。AI 生成的内容可能会有错误，怎么保证方案的专业性和准确性？可能需要人工审核，或者建立一套审核机制。
>
> 第三，**个性化和定制化**。每个客户的情况都不一样，怎么让 AI 生成的方案更有针对性，而不是通用模板？这个可能需要更多的客户数据和更智能的算法。
>
> 第四，**销售的接受度**。销售会不会觉得 AI 生成的方案太模板化，不愿意用？这可能需要在产品设计上更好地结合销售的工作流程，而不是替代他们。"

#### Q4: 你为什么想做销售相关的项目？
**参考回答：**
> "因为我本身有大客户销售的实习经历，对销售的工作流程和痛点比较了解。而且我觉得，AI 在 To B 销售领域的应用空间非常大。
>
> 销售是一个非常依赖经验和能力的岗位，一个好的销售和一个普通的销售，产出可能差好几倍。而 AI 可以把资深销售的经验沉淀下来，赋能给所有销售，这对企业来说价值很大。
>
> 另外，我觉得这个岗位（云与AI咨询销售）本身就是技术和销售的结合，我既有技术背景，又有销售实习经验，做这个项目也算是我对这个岗位的理解和实践。"

## 💡 演示技巧

### 1. 控制节奏
- 不要太快，也不要太慢
- 重点地方放慢，强调一下
- 整个演示控制在 5-8 分钟，不要太长

### 2. 突出亮点
- 效率提升（几小时 → 几十秒）
- 专业度（看起来像真的咨询顾问写的）
- 全栈能力（从设计到开发独立完成）
- 产品思维（不是为了做技术而做技术，是为了解决问题）

### 3. 结合岗位
- 自然地提到火山引擎、火山方舟
- 显示你对字节的产品和业务很了解
- 把项目和岗位需求结合起来

### 4. 真诚自信
- 不会的就说不会，不要瞎编
- 但要表现出你有思考、有想法
- 自信但不自大

## 🚀 加分项

如果时间充裕，可以展示这些：

### 1. 代码质量
- 打开 GitHub 仓库，展示清晰的代码结构
- 展示完善的 README 和文档
- 展示规范的提交记录

### 2. 技术深度
- 讲讲 RAG 的原理和你的优化
- 讲讲 Prompt Engineering 的经验
- 讲讲你对大模型应用的理解

### 3. 产品思维
- 讲讲你是怎么发现这个需求的
- 讲讲你是怎么设计功能的
- 讲讲你对未来的规划

---

## ⚠️ 注意事项

1. **不要夸大** - 是什么就是什么，不要吹牛皮
2. **不要纠结细节** - 面试官没问的，不要主动讲太细
3. **准备好被挑战** - 面试官可能会质疑你的方案，要虚心接受，同时表达自己的思考
4. **把面试官当客户** - 演示的过程，就是你销售能力的体现

---

## 🎉 最后

记住，这个项目只是一个载体，面试官真正想看的是：
- 你的技术能力怎么样
- 你的产品思维怎么样
- 你是不是一个会思考、能落地的人
- 你和这个岗位匹不匹配

所以，演示的时候不要只讲功能，要多讲**为什么这么做**、**你是怎么思考的**、**你学到了什么**。
